# 一键禁用（lock-mode）

在微聊里发 `/lock`，不用翻小天才 App 就能开关「上课禁用」「睡眠禁用」。

作者：赵小黑日记 · GPL-3.0

## 用法

| 发什么 | 效果 |
| --- | --- |
| `/lock` | 看状态（当前手表、两个禁用的开关和时段） |
| `/lock c` | 上课禁用 开↔关（取反） |
| `/lock c on` / `/lock c off` | 上课禁用 指定开关 |
| `/lock s` | 睡眠禁用 开↔关（取反） |
| `/lock s on` / `/lock s off` | 睡眠禁用 指定开关 |
| `/lock on` / `/lock off` | 两个一起开 / 一起关 |
| `/lock w` | 列出手表，标出当前那块 |
| `/lock w 2` | 切到第 2 块表 |

`c` `class` `上课` 都认，`s` `sleep` `睡眠` 也认。

输入示例：

```
/lock
狂笑的凯哥写论文 Z8
上课禁用 关
 8:00-11:30、13:00-16:00 周一~五
睡眠禁用 2/5 段开
 23:30-6:00、22:00-6:00 等
/lock c 上课 · /lock s 睡眠
/lock on|off 全开|全关 · /lock w 换表
```

```
/lock c
✓ 上课禁用 已开启
8:00-11:30、13:00-16:00 周一~五
```

## 几个已经踩过的坑

**上课禁用是「一键开关」，睡眠是「按时段开关」。**
上课禁用只有 `classSwitch` 一个总开关（`1` 开 / `0` 关）。
睡眠不同：它挂在「时间管理」里（`type=1`），可能有好几条时段，每条自带 `switchStatus`。
所以本插件对睡眠的处理是**全部时段一起开关**，状态显示成 `2/5 段开` 这种，让你一眼看到混合状态。

**睡眠时段可能是脏数据。**
实测一块表上出现过多条同名同时段的记录（三份「宝贝睡眠时间 21:10-07:30」）。
插件按条遍历，全部一起改，不会只改第一条就以为改完了。

**写完不重读，直接用写入返回值。**
读一次状态要 2 秒左右，写完再重读会超过 `onMessage` 的 6 秒上限。
所以 `/lock c` 之类的写操作是「读一次 → 写 → 按写入结果回复」，不再二次确认。
如果你要绝对确认，发一次 `/lock` 看状态即可。

**写操作全在后台跑。**
`onMessage` 里只做解析，真正的读写在 `jz.timers.after(0, ...)` 里执行。
超时了也不会被宿主记成钩子失败，出错会单独回一条消息告诉你原因。
另有一个模块级 `busy` 锁，防止连点两次导致状态错乱。

**回上课禁用时只传声明过的字段。**
服务端会拒绝多余字段，所以只回传 `classId / classWeek / createTime / holidaySwitch / id / timePeriod / title / type / watchId`，再补 `classSwitch` 和 `tempSwitch`。

## 权限

只要三个：

- `chat.send` —— 回消息
- `watch.read` —— 读 `getClassModes` / `getTimeManageList` / 手表列表
- `watch.write` —— 写 `updateClassMode` / `updateTimeManage`

没有 `http`，不联网；没有 `chat.read`，读不到聊天记录。
这两个写接口不在宿主的 `API_DENY` 名单里（那份名单只挡解绑、删好友、迁移账号这类不可逆操作）。

## 面板

WebUI 导航栏「一键禁用」里能直接看到两块开关和时段，切手表也是个下拉框。
面板和手表指令走的是同一套接口。

## 配置

| 键 | 说明 |
| --- | --- |
| 指定手表 ID | 填了就固定这块；留空 = 按 `/lock w` 选中的那块，没选过则优先在线的，再退回第一块 |
| 启用 | 关掉就整个插件不响应 |

## 打包

```bash
python tools/pack-plugin.py C:\Users\liu\.watch-parent-cli\plugins\lock-mode
```

输出 `lock-mode-1.0.0.zip`，根目录直接是 `plugin.json`，不带 `data/` 和隐藏文件。
WebUI →「插件」→「上传插件（.zip）」安装，同 `id` 视为升级。
